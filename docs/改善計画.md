## Phase 1: リソースリーク修正

長時間運用で確実に顕在化するクラッシュ要因を排除する。

### ForkJoinPool のシャットダウン

- [x] `FileScanner` に `shutdown()` メソッドを実装（`pool.shutdown()` → `awaitTermination(5s)` → 失敗時 `shutdownNow()`）
  - 場所: `src/main/java/com/example/diskanalyzer/service/FileScanner.java`（実体は `service/` 配下）
- [x] `ScanTask.call()` の finally ブロックで `FileScanner.shutdown()` を呼び出し
  - 場所: `src/main/java/com/example/diskanalyzer/controller/ScanTask.java`
- [x] `DuplicateDetectionService` に `shutdown()` を実装
  - 場所: `src/main/java/com/example/diskanalyzer/service/DuplicateDetectionService.java`
  - 補足: pool を per-call 化し、`findDuplicates()` の try-finally で確実に解放。`shutdown()` は冪等
- [x] `IncrementalScanService` の ForkJoinPool を `incrementalTask.setOnSucceeded` / `setOnFailed` の両方で確実に shutdown
  - 場所: `src/main/java/com/example/diskanalyzer/service/IncrementalScanService.java`
  - 補足: pool / FileScanner を per-call 化し、各メソッド内 try-finally で解放
- [x] `MainController.handleIncrementalScan` でタスク完了時に `incrementalService.shutdown()` を呼び出し
  - 補足: `handleFindDuplicates` 側でも `duplicateService.shutdown()` を対称的に追加

### ストリーム / Process の解放

- [x] `ScanCacheService` の全 `Files.list()` 呼び出しを `try (var stream = Files.list(...))` に置換（5箇所）
  - 場所: `ScanCacheService.java` の `getAllSnapshots` / `deleteAllSnapshots` / `getCacheSize` / `clearCache` / `cleanupOldCache`
- [x] `FileManagerService` の `Runtime.getRuntime().exec()` 結果 `Process` の `getInputStream()` / `getErrorStream()` を try-with-resources で確実にクローズ
  - 場所: `FileManagerService.java` の `showInFinder` / `showInExplorer` / `showInLinuxFileManager` / `isCommandAvailable`
  - 補足: 共通ヘルパ `closeProcessStreams(Process)` で input/error/output 全ストリームを finally で確実にクローズ

### 検証

- [x] `./gradlew build` 通過（OpenJDK 21 + Gradle 9.4.1 にて確認、コミット `d0102d3`）
- [x] 手動: 同一セッションで「フルスキャン → 増分スキャン → 重複検出」を5回繰り返し、`jconsole` 等でスレッド数が単調増加していないことを確認

## Phase 2: セキュリティ・OS依存の堅牢化

コマンドインジェクションと誤削除を防止する。

### コマンド実行の安全化

- [ ] `FileManagerService` を `Runtime.exec(String)` から `ProcessBuilder(List<String>)` に置換（4箇所）
  - 場所: `FileManagerService.java:65, 68, 98, 101, 141, 144`
  - 効果: スペース・特殊文字を含むパスを安全に渡せる、コマンドインジェクション防止

### 削除安全性

- [ ] `FileDeleteService.isSystemFile` を文字列マッチから `Path.startsWith()` ベースの厳密判定に変更
  - 場所: `FileDeleteService.java:122-151`
  - macOS: `/System`, `/Library`, `/Applications`, `/Users/Shared`
  - Windows: `%WINDIR%`, `%PROGRAMFILES%`, `%PROGRAMFILES(X86)%`
  - 実装時に `Path.toRealPath()` でシンボリックリンク解決
- [ ] `FileDeleteService.deleteDirectoryRecursively` の例外を集約し、失敗があれば最終的に IOException を伝播（部分削除で success を返さない）
  - 場所: `FileDeleteService.java:70-81`

### エラー表示の安全化

- [ ] エラーダイアログから `e.getMessage()` の直出しを撤去し、汎用メッセージに置換。詳細は `logger.error(..., e)` に残す
  - 場所: `MainController.java:449, 529`

### ログ出力先の OS 別対応

- [ ] `logback.xml` を編集し、OS別ログディレクトリに対応
  - macOS: `~/Library/Logs/LumiDisk/`
  - Windows: `%LOCALAPPDATA%/LumiDisk/logs/`
  - その他: `~/.lumidisk/logs/`
  - 場所: `src/main/resources/logback.xml:12`

### 検証

- [ ] スペース含むパス（例: `/tmp/foo bar/`）で「Finderで表示」が正しく動くこと
- [ ] `/System/Library/CoreServices/` 配下を選択しても削除メニューが無効化されること
- [ ] 起動後、CLAUDE.md記載の OS別ログパスにファイルが作成されること

## 進め方の推奨

1. **フェーズごとに個別コミット**（Conventional Commits 形式）
   - 例: `fix(scanner): ForkJoinPool を確実にシャットダウンする`
   - 例: `refactor(controller): MainController からダイアログ Controller を抽出`
2. **各フェーズ完了時に手動動作確認**（テスト基盤が整うまで）
   - 確認シナリオ: フルスキャン → 増分スキャン → 重複検出 → ファイル削除 → Finder/Explorer 表示
3. **Phase 1 → 2 → 3 → 4 の順序を推奨**
   - Phase 2 以降は Phase 1 のリソース解放を前提とする箇所がある
