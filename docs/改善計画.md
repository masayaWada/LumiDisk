  - 場所: `src/main/java/com/example/diskanalyzer/controller/ScanTask.java`
- [x] `DuplicateDetectionService` に `shutdown()` を実装
  - 場所: `src/main/java/com/example/diskanalyzer/service/DuplicateDetectionService.java`
  - 補足: pool を per-call 化し、`findDuplicates()` の try-finally で確実に解放。`shutdown()` は冪等
- [x] `IncrementalScanService` の ForkJoinPool を `incrementalTask.setOnSucceeded` / `setOnFailed` の両方で確実に shutdown
  - 場所: `src/main/java/com/example/diskanalyzer/service/IncrementalScanService.java`
  - 補足: pool / FileScanner を per-call 化し、各メソッド内 try-finally で解放

### ストリーム / Process の解放

## Phase 2: セキュリティ・OS依存の堅牢化

コマンドインジェクションと誤削除を防止する。

### コマンド実行の安全化

- [x] `FileManagerService` を `Runtime.exec(String)` から `ProcessBuilder(List<String>)` に置換（4箇所）
  - 場所: `FileManagerService.java` の `showInFinder` / `showInExplorer` / `showInLinuxFileManager` / `isCommandAvailable`
  - 効果: スペース・特殊文字を含むパスを安全に渡せる、コマンドインジェクション防止
  - 補足: Phase 1 で残っていた `Runtime.exec(String)` deprecation 警告も解消

### 削除安全性

- [x] `FileDeleteService.isSystemFile` を文字列マッチから `Path.startsWith()` ベースの厳密判定に変更
  - 場所: `FileDeleteService.java`
  - macOS: `/System`, `/Library`, `/Applications`, `/Users/Shared`, `/usr`, `/bin`, `/sbin`
  - Windows: `%WINDIR%`, `%SystemRoot%`, `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%ProgramW6432%`
  - Linux/その他: `/etc`, `/var`, `/usr`, `/bin`, `/sbin`, `/boot`, `/proc`, `/sys`
  - 実装: 起動時に `resolveSystemRoots()` で OS 別ルートを `toRealPath()` 解決し、対象パスも `normalizeForCheck()` で正規化してから `startsWith()` 判定。正規化失敗時はフェイルセーフで保護対象扱い
- [x] `FileDeleteService.deleteDirectoryRecursively` の例外を集約し、失敗があれば最終的に IOException を伝播（部分削除で success を返さない）
  - 場所: `FileDeleteService.java`
  - 補足: `Files.walk()` を try-with-resources 化、失敗を `Collections.synchronizedList` に蓄積、最後に `addSuppressed` で集約 throw

### エラー表示の安全化

- [x] エラーダイアログから `e.getMessage()` の直出しを撤去し、汎用メッセージに置換。詳細は `logger.error(..., e)` に残す
  - 場所: `MainController.java` のダイアログ 2 箇所 (449, 529) + statusLabel 5 箇所 (235, 324, 351, 572, 624, 669, 714) を併せて全 7 箇所処理
  - 補足: 計画書スコープを拡張し、同種の脆弱性として一貫処理

### ログ出力先の OS 別対応

- [x] `logback.xml` を編集し、OS別ログディレクトリに対応
  - macOS: `~/Library/Logs/LumiDisk/`
  - Windows: `%LOCALAPPDATA%/LumiDisk/logs/`（取得不可なら `~/LumiDisk/logs/`）
  - その他: `~/.lumidisk/logs/`
  - 実装: `MainApp` の static イニシャライザで OS 判定し `LUMIDISK_LOG_DIR` system property を設定、`logback.xml` で `${LUMIDISK_LOG_DIR:-logs}` を参照

### 検証

- [x] `gradle build` 通過（OpenJDK 21 + Gradle 9.4.1 にて確認、コミット `b352c1b`）
- [ ] スペース含むパス（例: `/tmp/foo bar/`）で「Finderで表示」が正しく動くこと
- [ ] `/System/Library/CoreServices/` 配下を選択しても削除メニューが無効化されること
- [ ] 起動後、CLAUDE.md記載の OS別ログパスにファイルが作成されること

### 副次的な発見と修正（スコープ外だが重要）

Phase 3 のテスト基盤整備中に、スナップショット永続化の **silent バグ** を発見し併せて修正:

- `FileTime` が Jackson 既定で serialize 不能 → 専用 Module で ISO-8601 文字列に変換
- `ScanSnapshot` / `FileNode` に `@JsonCreator` がなく deserialize 不能 → コンストラクタに付与
- `FAIL_ON_UNKNOWN_PROPERTIES` を無効化（`FileNode.extension` 等 derived field 対応）

これにより `IncrementalScanService` の増分スキャンが本来の差分動作で動くようになる（従来は保存失敗 → フルスキャンに常時フォールバックしていた）

## 進め方の推奨

1. **フェーズごとに個別コミット**（Conventional Commits 形式）
   - 例: `fix(scanner): ForkJoinPool を確実にシャットダウンする`
   - 例: `refactor(controller): MainController からダイアログ Controller を抽出`
2. **各フェーズ完了時に手動動作確認**（テスト基盤が整うまで）
   - 確認シナリオ: フルスキャン → 増分スキャン → 重複検出 → ファイル削除 → Finder/Explorer 表示
3. **Phase 1 → 2 → 3 → 4 の順序を推奨**
   - Phase 2 以降は Phase 1 のリソース解放を前提とする箇所がある
